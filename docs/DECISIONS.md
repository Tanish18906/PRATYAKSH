One line per ambiguity choice or config change (before/after numbers for ENGINE tuning).

- [engine P0] Fixture event `source` = `log_source` of `from_loc` (export -> src:db, wh/bucket moves -> src:wh/src:bucket, per 04 sec 2.4 and H2); `meta.artifact_id` is set on every event whose object is an `art:`.
- [engine P0] H6 run B (canary_hits = []) is not a separate fixture file; tests deep-copy `build("H6")` and clear `canary_hits` (04 lists only H1..H8.json).
- [engine P0] H6 canary registry hashes are `h64(b"mini-test-key", "canary:<id>:<column>")`, deterministic and arbitrary as 04 allows.
- [engine P0] `tests/engine/test_fixtures.py` carries a local structural check of H1..H8 because `scripts/validate.py` (Anmol, Phase 1) does not exist yet.
- [engine P1] OVERRIDE OWNERSHIP: api granted by Tanish for `backend/app/config.py` only; it holds exactly the ENGINE dict from 03 sec 3.
- [engine P1] Gate needs H1 and H6 path assertions, so Phase 1 `paths.py` has M1 (observed) + M2 (hidden move to leak location) + fallback only, and `rank.py` has the softmax with no anomaly term. M3, M4, anomaly (stage 4), graph, chokepoints, evidence requests stay Phase 2/3. `graph` is `{nodes: [], edges: []}` for now.
- [engine P1] `origin_ranking` is a top-level TraceResult key `[{artifact_id, probability}]` as 03 sec 9 and 04 use it (contract has no such field, see QUESTIONS.md). Pinned: `[{pinned, 1.0}]`.
- [engine P1] Candidate sort ties and path order never use artifact ids; enumeration order follows 03 sec 7 `(kind, to_loc, actor, event_id)`; `trace_id` is "trc:" + scenario id suffix.
- [engine P2] Stage 7 (`recommend`, 03 sec 11) was built in Phase 2 although 05 lists it for Phase 3, because H5 asserts `recommended_evidence`. Stage 6 chokepoints stay Phase 3 (`chokepoints = []`).
- [engine P2] Baseline std uses population std (`statistics.pstdev`), floored at SIGMA_FLOOR; 03 sec 8 says only "std".
- [engine P2] Graph edge ids for hidden hops are `e:{from}>{to}:inferred:hid:{actor}` (03 sec 12 says `hid`); two actors can hide the same from/to pair and must not merge.
- [engine P2] "High loss" in the stage 7 request text means loss_estimate >= LOSS_DEFAULT (0.4); 03 sec 11 gives no number.
- [engine P2] A pinned artifact that fails a hard rule is still used (canary wins); scored with origin_fit 0.0 and a note.
- [engine P2] Evidence list order: fingerprint, all observed hops, all inferred hops, anomalies (03 sec 13 order), not hop order.
- [engine P3] Chokepoint `label` and `action_text` both use the 03 sec 10 template text (the spec gives one set for both). The contract's sample "Revoke bulk download for Ravi Menon on bi-warehouse" is illustrative; templates win.
- [engine P3] Greedy selection uses mass on still-uncovered paths; the reported `marginal` is the item's mass over all enumerated paths; ties go to the smaller item id. Chokepoints are not filtered by a minimum mass (03 sec 10 sets none), so a low-mass third card is possible.
- [engine P3] Perf: `alt_actors` compares ISO strings instead of parsing timestamps per event (0.74 s to 0.12 s on a 3,224-event, 50-actor, 9-artifact synthetic scenario). No config or output change.
- [engine P5 fix] Export with row_count 0 made specificity divide by zero (found by randomized self-test, approved by Tanish); ratio now falls to the 0.01 clip floor.
- [api P0] `models.py` uses `extra="forbid"`, so a scenario carrying `truth`, `case_key` or any undocumented key fails validation. It also adds `origin_ranking` (artifact_id, probability) to TraceResult because 03, 04 and the engine use it; docs/01 text is NOT edited yet, Tanish to confirm and announce to Anmol (see QUESTIONS.md).
- [api P0] Timestamps and sketch hashes are pattern-checked in models (`...Z` seconds precision, 16 lowercase hex).
- [api P0] Masking: unknown columns become `***` (treated as personal); `dob` not in ISO form becomes `***`; None and "" stay ""; values not longer than the kept parts are fully starred.
- [api P0] `CLAUDE.md` is kept as the repo-specific file already present (restates AGENTS.md rules plus architecture) instead of a byte copy of AGENTS.md; AGENTS.md stays the neutral source.
- [api P0] Plain `pytest -q` needs `backend/app/__init__.py` and `backend/tests/__init__.py` tracked (pytest inserts `backend/` into sys.path through the `tests` package). They were untracked before; now committed. `app/common/__init__.py` is still untracked (engine folder); it works as a namespace package.
- [api P0] README: removed an invented benchmark bar chart (no benchmark has run), "Calibrated" and "Zero-Exposure" wording (guardrails), and `--host 0.0.0.0` from the run command (spec command binds localhost).
- [api P0] venv lives at repo root `.venv/` (gitignored); requirements stay unpinned as written; starlette prints a deprecation warning about httpx in TestClient, harmless.
- [api P1] Simulator hook: `main._sim()` returns `app.sim.generator` only if it defines `generate_scenario`. Without it `POST /api/scenario/generate` answers 409 `not_ready` (the contract's code for this) and H1..H8 are registered at startup by reading `backend/tests/fixtures/H*.json` (JSON read, no import of test code). Once the simulator lands, `generate` calls it and fixtures are no longer loaded.
- [api P1] The API validates every scenario through `PublicScenario` before use (a producer emitting `truth`, `case_key` or unknown keys gets 500 `engine_error`), and re-masks any preview value that contains no `*`, so a simulator bug cannot leak a raw value. `to_summary` from the simulator is not needed: the summary is built from the public scenario.
- [api P1] Floats are rounded to 4 decimals at the API boundary for every response. `GET /api/scenario/{id}?full=true` is dumped with `exclude_unset` so optional EventMeta fields stay absent.
- [api P1] Audit entries are written only after a request succeeds, exactly one per generate / export / trace. Failed requests write none. Numbering continues from the lines already in the JSONL file.
- [api P1] Errors: body validation 400 `bad_request` (log_loss outside 0 to 0.8, bad archetype, extra keys, top_k outside 1 to 20), unknown id or message 404 `not_found`, engine or contract failure 500 `engine_error`, unknown routes 404 `not_found`. `top_k` upper bound 20 is mine; the contract gives none.
- [api P1] `leak/export` returns 404 when the message id is unknown or has no attachment. Audit `object_id` for export is the leak sample id.
- [api P2] `POST /api/reveal` check order: reason (400 `reason_required`, at least 8 characters after trimming), scenario (404), field in leak columns and row_index in range (400 `bad_request`), private store available (409 `not_ready`), simulator call (500 `engine_error` on failure). The audit entry is written only after a value was obtained; failed attempts write none. Response carries `Cache-Control: no-store`.
- [api P2] Reveal audit `object_id` is `{leak_sample_id}#{row_index}` so the entry says which row was shown; `field` and `reason` use the contract fields.
- [api P2] Simulator functions are looked up by name in `app.sim`, then `app.sim.generator`, `leakfile`, `store` (docs/02 sec 3 lists the functions but not their modules). `_sim()` returns None unless `generate_scenario` exists.
- [api P2] `GET /api/audit` returns entries in write order, optional `scenario_id` filter, validated through `AuditEntry`.
- [api P3] `POST /api/canary/alert`: the alert dict comes from the simulator's `canary_alert` when a bundle exists, otherwise it is built from the public canary registry (`ts` = found_ts, generic message). The trace that goes with it runs on a COPY of the scenario in which the alerted canary is added to `canary_hits`, so an alert pins the origin to that export; the stored scenario is untouched. Unknown canary 404, canary mode off 400. One audit entry (`canary_alert`), no extra `trace` entry.
- [api P3] That alert-driven trace replaces the cached trace for the same trace id, so `GET /api/report/{trace_id}` after an alert reports the pinned result.
- [api P3] `GET /api/report/{trace_id}`: uses the cached trace, otherwise recomputes from `scn:` + the id suffix (survives a restart); unknown id 404; one `report_export` audit entry per download. Report has no wall clock, so the same trace gives the same HTML. The vendor-boundary sentence appears when a top-3 path has a `send` hop to an external location or touches an `sftp` location.
- [api P3] Report wording avoids the word "calibrated", states no deadline, and always carries "Verify current legal timelines with counsel."
- [api P3] Response scrub: every string in every response except reveal is passed through an email mask (first character, `***`, domain). It exists so a producer leaking an address in free text (a Telegram message, a canary message) cannot reach the UI.
- [api P3] `make_demo_bundle.py` adds a `--fixture H1..H8` flag (not in the docs) because the simulator is not available; without it and without a simulator the script exits 1 with a message. It writes audit entries to a temporary file, never to the real log, and validates the result as a `DemoBundle`. Default output is `frontend/public/demo.json`; I did not run that default (Anmol's folder).
- [api P3] Inject: unknown actor 400, unknown base 404, no simulator or no bundle 409. Log-loss regeneration needs no api code: `generate` with another `log_loss` gives the simulator's new scenario id.
- [api P4] Benchmark runner (`bench/run.py`) takes the generator as a parameter and reads ground truth only inside itself; the API runs it in a daemon thread and exposes aggregated `MethodStats` only. Archetype per seed is `archetypes[seed % len(archetypes)]` (the spec's `["A1","A2","A3"][s % 3]` for the default list); seed 42 is skipped; scale `bench`, canary off.
- [api P4] Loss keys in `origin` and `actor` are `str(float(loss))` ("0.0", "0.2", ...). Benchmark ids are `bench:0001`, `bench:0002`, ... (contract has no prefix for them).
- [api P4] `tuned_on` is always "seeds 0-49". `reported_on` is the requested range, with " (includes tuning seeds)" appended if the range starts at 49 or below, so a number from tuning seeds cannot be mistaken for a held-out one. `note` is always the synthetic-data sentence.
- [api P4] An engine or generator exception in any scenario sets status `failed` (results gathered so far are kept; a crashed engine run counts as the worst rank, a crashed generator run is skipped). No silent success. Sanity gates (04 sec 6.4) are `metrics.sanity_gates` and are printed by the CLI; they are not enforced by the HTTP endpoint, the five hand spot checks stay manual.
- [api P4] Baselines break ties by the scenario's own actor order; origin baselines ignore exports created after `found_ts` (04 sec 6.3). `last_accessor` counts events on any artifact or on the dataset named "customers" (`ds:customers` in the simulator, `ds:cust` in fixtures).
- [api P4] Request limits are mine: `seed_range` first <= last with fewer than 1000 seeds, `loss_levels` between 0 and 0.8 (same as `generate`), at least one archetype.
- [api P4] `make_demo_bundle.py --benchmark FILE` embeds a saved `BenchmarkResult` (written by `python -m app.bench.run --out FILE`) so `demo.json` can carry the final numbers; the file is validated, a bad file exits 1.
